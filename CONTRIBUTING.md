# Contributing to JellyRock

Thanks for your interest in contributing. JellyRock is a free and open-source Jellyfin client for Roku, with a companion server plugin and its own websites. Every kind of contribution is welcome: bug reports, fixes, features, translations and docs.

This guide applies to every repository in the organization. Each repository's README explains how to build it and links its developer guide.

## Ask a question

Ask in [GitHub Discussions](https://github.com/jellyrock/jellyrock/discussions). Other users in the [Matrix chat](https://matrix.to/#/#jellyrock-app:matrix.org) can often help too.

## Report a bug or suggest a feature

Open an issue in the repository it's about. If you're not sure which one, use [JellyRock's](https://github.com/jellyrock/jellyrock/issues/new/choose).

## Translate

JellyRock is translated on [Weblate](https://translate.jellyrock.app/projects/jellyrock/). You don't need to set anything up to help.

## Pull requests

- Keep each PR to one change.
- Branch from `main` and open the PR against `main`.
- Follow the repository's developer guide: it lists the checks to run and any rule for PR titles.
- The GitHub Actions checks must pass before a PR can merge.

## AI assistance

AI-assisted contributions are welcome, with two expectations:

- **A person reviews the change before submitting it.** You must have read it, understand what it does, and be able to explain and defend it in review. Don't open a PR you couldn't walk through yourself.
- **You are accountable for it.** AI assistance doesn't change who is responsible. The same bar for correctness, licensing and quality applies as for code you wrote by hand.

The line is not AI or human. It is work someone owns and reviewed, or work nobody did. Use whatever tools you like, and stand behind the result.

## Security

Found a vulnerability? Don't open a public issue. Report it privately as the [security policy](https://github.com/jellyrock/.github/blob/main/SECURITY.md) describes.
